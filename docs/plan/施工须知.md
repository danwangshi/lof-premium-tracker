## 3. 数据原则（用户原话，最高优先级）

> 「对于一批数据，我们没有实时的正确符合时间戳的数据 就应该使用空值 避免误导用户」

**拿不到带正确时间戳的数据，就返回空值。** 不许用旧值、估算值、默认值蒙混过去。
宁可前端显示 `--`，也不要显示一个看起来合理但其实是错的数字。

这条比「页面好看」「指标齐全」都重要。金融数据里一个静默错误的数字比一个空格危险得多。

## 4. 地雷清单（每条都真的炸过）

### 4.1 数据库

| 地雷 | 说明 | 正确姿势 |
|---|---|---|
| `statement_timeout = 5s` | **静默**杀掉分析型 / 迁移查询，不报错只返回空 | 迁移脚本开头 `SET statement_timeout = 0`，或用 `PGOPTIONS="-c statement_timeout=0"`；大操作分片 |
| `CREATE INDEX CONCURRENTLY` | 不能在事务里跑；超 5s 会被杀并留下 `INVALID` 索引 | `PGOPTIONS="-c statement_timeout=0 -c lock_timeout=0"`；失败先 `DROP INDEX` 再重来 |
| `fund_est_nav` | 占全库 **91%**（1895 MB / 914 万行），每天 164 个切片但**只有 1 个会被读** | 任何全表扫描都是事故，必须走索引 |
| `daily_kline` | **死表**，只有 v1 用 | 别往里写 |

### 4.2 服务器

| 地雷 | 说明 |
|---|---|
| **内存只有 1673 MB，且没有 swap** | 一旦打满直接 OOM Kill，没有缓冲。PostgreSQL + Redis + uvicorn 三件共处。**别跑并行重活** |
| **约束 C1：不许调大 Redis `maxmemory`** | 目前 512 MB，峰值已顶到 515.97 MB。只能靠**缩减键体积**解决，不能靠加内存 |
| Redis **没有持久化** | `appendonly no` + `save` 为空 → 重启即全量丢缓存。改缓存相关逻辑时把这点算进去 |
| 磁盘 40 GB / 已用 18 GB | 有余量但不多 |

### 4.3 网络 / 工具（Windows 本机特有的坑）

| 地雷 | 现象 | 正确姿势 |
|---|---|---|
| `curl.exe` 连不通源站 | 总是 `code=000` | 用 Node 的 `fetch` 或 Playwright / Chromium |
| git 全局代理是**死的** | `http.proxy=http://127.0.0.1:7897` 已关，git 会超时 | 一律 `git -c http.proxy= -c https.proxy= <cmd>` |
| `gh pr create` / `merge` 间歇性失败 | 网络 EOF / 超时 | 重试循环有效，别当成真失败 |
| SSH 有 `POSIXLY_CORRECT` | CRLF 行尾的 `.sh` 会炸：`free: invalid option -- '`、`df: '/'$'\r'` | 上传脚本**必须 LF 行尾**：`Set-Content -Value ($L -join "\`n") -Encoding ascii -NoNewline` |
| PowerShell 嵌套引号 | 会毁掉 `ssh` / `python3 -c` | **本地写 `.sh` → `scp` → 远端 `bash`**，绝不内联长命令 |
| API 前缀 | 写 `/health`、`/api/funds` 会 404 | 只有 **`/api/v1/...`** 存在 |
| 线上 `index.html` 比本地多 ~367 字节 | 看起来像改动没生效 | 那是 Cloudflare 注入的 Web Analytics beacon，**正常** |

### 4.4 前端

| 地雷 | 说明 |
|---|---|
| **手工版本号做缓存失效** | `index.html` 里写的是 `js/app.js?v=42`、`css/style.css?v=29`。**改了 JS/CSS 必须同步把版本号 +1**，否则用户拿不到新代码 |
| 无构建步骤 | 没有打包器、没有 `tsconfig.json`。改了就是改了，没有编译期保护 |
| 零测试 | 前端没有任何自动化测试。**所以你必须自己端到端验证线上** |

### 4.5 Git

| 地雷 | 说明 |
|---|---|
| `git commit -m` 与 `-F` **不能同时用** | 二选一 |
| `git commit -F` 把文件第一行当主题 | **必须自己补真正的主题行** |
| 带 BOM 的文件 | 会让 `git status --porcelain` 第一行看起来「已修改」。无害，别追 |

### 4.6 舍入语义（**最阴的一条**）

后端有 **68 处 `round()`，分布在 12 个文件**，四种语义互不相同：

| 输入 | Python `round(x)` | JS `Math.round(x)` | Python `round(x,2)` | JS `toFixed(2)` | JS `Math.round(x*100)/100` |
|---|---|---|---|---|---|
| 2.5 | **2** | **3** | — | — | — |
| 0.5 | **0** | **1** | — | — | — |
| 0.125 | — | — | **0.12** | **0.13** | 0.13 |
| 2.675 | — | — | **2.67** | 2.67 | **2.68** |

Python 是**银行家舍入**，PostgreSQL 是四舍五入，JS 三种写法互相也不一致。
**差异正好落在用户直接看的位数上**（溢价率 2 位、估算净值 4 位）。

> **把 Python 的 `round()` 直译成 `Math.round()` 会静默改变用户看到的数字。**
> 涉及数值计算时，用统一的 decimal 库并**显式声明舍入模式**；SQL 里的 `round()` 留在 SQL 里，不要搬到应用层。
> 对拍/测试必须专门覆盖 `.5` 边界。

## 5. 怎么干活

### 5.1 流程

1. **读本文件 + 你的任务书 + 任务书里引用的文档**
2. `request_input` 问清任何歧义 —— **不要猜**
3. 动手前先说计划（复杂改动尤其）
4. 改 → **自己验证** → 拿证据
5. 开分支 → commit → push → 开 PR
6. `report_task` 提交结果，**报告里贴证据**

### 5.2 分支与 PR

- 分支名：`<type>/<短描述>`，如 `fix/est-nav-close-cutoff`
- commit message：`type(scope): 中文描述`
  `type` ∈ `fix` / `feat` / `refactor` / `docs` / `test` / `perf` / `chore`
- **一 PR 一件事**
- PR 正文用三段式：

```markdown
## 问题
（为什么要改，现象是什么）

## 改动
（改了什么，为什么这样改）

## 验证
（怎么验证的，贴命令输出 / 实测数字 / 截图）
```

- PR 标题里**不要用内层双引号**，需要引号用「」
- 分支保护开启：**普通 merge 会被拒**，需要 `gh pr merge <n> --squash --admin`
- push / 开 PR / 合并**由你自己完成**，不要问「要不要我推」

## 6. 验证：什么才算「做完了」

**「我改好了」不算完成。** 报告里必须有下面某一项真实证据：

| 改动类型 | 需要的证据 |
|---|---|
| 前端 | **线上** URL 实测（Playwright 断言或截图），不是本地截图 |
| 后端 | 真实 HTTP 响应（Node `fetch` 打 `https://api.jinkuaicha.com/api/v1/...`） |
| 数据 | SQL 查询结果（行数 / 覆盖率 / 体积），在源站跑 |
| 性能 | 改动前后的**实测耗时数字**，不是估计 |
| 测试 | `pytest` 的真实输出（在 `/opt/jinkuaicha/backend-v2`） |

## 7. 关键业务口径

| 概念 | 公式 |
|---|---|
| 溢价率 | `(收盘价 - 单位净值) / 单位净值 × 100%` |
| 盘中溢价率 | `(实时价 - 盘中估值) / 盘中估值 × 100%` |
| 三日均溢 | 近 3 个交易日收盘溢价率的算术平均 |
| 换手率 | `成交量(手) × 100 / 场内流通份额(份) × 100%` |
| 涨跌幅 | `(当日收盘价 - 昨日收盘价) / 昨日收盘价 × 100%` |

**「估算净值」与「净值」是两个不同的量**，前端展示时**必须让人能分辨**。估算净值是盘中推算，真实净值是收盘公布。把估算值当净值展示会误导用户。

## 8. 汇报格式

```

（一句话）

（命令 + 真实输出 / 实测数字 / 截图路径）

## 上线状态
（已部署并线上验证 / 仅本地验证 / 未部署）
```
